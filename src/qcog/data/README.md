# Datasets

`benchmarks.json` contains **illustrative synthetic data generated by Q-Cog itself**, with a fixed seed, so
that the fitting and model-comparison workflow can be exercised without copying anyone's dataset.

**It is not the published values from any paper.** The qualitative *shape* of the data was chosen to resemble
the patterns reported in the cited literature, but every number was produced by this library, and the file
itself records the generating parameters, the seed and the provenance note.

Two datasets are included:

| Key | Design | How it was generated |
| --- | --- | --- |
| `question_order_illustrative` | two dichotomous questions, asked in both orders, 400 simulated participants per order | sampled from the `question-order` model at the recorded parameters |
| `conjunction_illustrative` | Linda-style conjunction design | evaluated with the `conjunction-fallacy` model at the recorded parameters |

## Using your own data

Both the CLI and the fitter accept a flat mapping from a response key to an observed probability (and,
optionally, counts):

```json
{
  "AB: p(A=yes)": 0.79,
  "AB: p(B=yes)": 0.74,
  "AB: p(B=yes|A=yes)": 0.91,
  "AB: p(B=yes|A=no)": 0.09,
  "BA: p(B=yes)": 0.50,
  "BA: p(A=yes)": 0.50,
  "BA: p(A=yes|B=yes)": 0.91,
  "BA: p(A=yes|B=no)": 0.09
}
```

```bash
qcog fit question-order my_data.json
```

The response keys a model predicts are documented by its `predict` method and printed by
`python -c "from qcog import get_model; print(sorted(get_model('question-order').predict()))"`. Pass `--counts`
(or the `counts=` argument of `qcog.core.fitting.fit`) to switch on the multinomial likelihood, the
chi-square-style weighting and AIC/BIC.

Real data should be attributed to its source: put the citation in your project page, not only in the file.
