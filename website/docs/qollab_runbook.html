Runbook: running and publishing Q-Cog on Qollab

This is the operational checklist for getting the project onto Qollab and keeping it runnable there. It assumes no prior Qollab experience.

1. What Qollab runs

Qollab executes published projects on its free simulators, including IonQ's simulator. Q-Cog satisfies the "runs on a free local simulator" requirement in the strictest sense: the exact and sampled backends use Qiskit's own Statevector and DensityMatrix classes, and the aer backends use qiskit-aer. No credentials are required for any of that.

Design choices that make the project easy to host:

  • no notebooks, no compiled extensions, no data downloads;
  • src layout with a pyproject.toml, so pip install qcog or pip install -e . both work;
  • a single entry point (qcog) plus a static website that needs no server and no configuration;
  • the report generator writes a self-contained HTML file - no CDN, no fonts to fetch, no JavaScript;
  • all randomness is seeded, and the analytic backends are exact and deterministic, so a published artefact can be regenerated byte-for-byte from the parameters printed next to it.

2. Minimal dependency set

numpy>=1.26  scipy>=1.11  pandas>=2.0  matplotlib>=3.8  qiskit>=2.0  qiskit-aer>=0.15

Optional: qiskit-ionq>=0.5 (the IonQ submission path).

If the Qollab environment pins an older Qiskit, check the two API touch points the library uses: qiskit.quantum_info.{Statevector, DensityMatrix, Operator, Kraus, partial_trace, schmidt_decomposition} and qiskit.circuit.library.{StatePreparation, UnitaryGate}. qcog evidence will tell you immediately whether the environment is consistent: it cross-checks the analytic and circuit paths.

3. Reproduce the artefacts

python -m pip install -e ".[app]"
python -m pytest -q                 # 128 tests, about a minute
qcog evidence                       # the self-check table
qcog report --out out/qcog_report.html --markdown
python demos/examples/05_catalogue_report.py

out/qcog_report.html is the file to publish or attach: one page, all twenty-three models, their figures, their text descriptions, their data tables, their caveats, and the evidence table.

4. Publish on Qollab

  1. Create the project on Qollab and connect the repository (or upload the archive). The repository root contains pyproject.toml, README.md, LICENSE and the docs, so nothing needs restructuring.
  2. Set the licence to MIT. It is already LICENSE in the root; Qollab's licence field should match.
  3. Add the attribution line to the project description: This effort is supported by Qollab & IonQ.
  4. Project page text: paste docs/project_page.md (or the shorter summary below). It covers what the submission does, what problem it explores, how to run it, and how to replicate or extend it - the four things the submission rules ask for.
  5. Demo video: a public link that opens without signing in (YouTube unlisted works, a Vimeo link works, a direct link to an mp4 works if it is public). Script: docs/demo_video_script.md.
  6. Keep it available for twelve months - the participating obligation. The repository is self-contained, so availability reduces to keeping the repo and the video link alive.
  7. Add the project page section "How to run" with the four commands from section 3 above.

Short project-page summary (paste-ready)

Q-Cog is a Qiskit-native Python library and interactive platform for quantum-probability models of human judgement, decision making and collective behaviour. It contains 23 documented models in four modules (individual cognition, concepts and memory, strategic decisions, groups and networks). Every model runs on a free local simulator, reports the classical baseline for the same situation, states its own caveats, produces accessible figures with text descriptions, and can be fitted to observed response frequencies. Verification is executable: qcog evidence prints a table of self-checks, including parity between the analytic engine and compiled circuits, the parameter-free QQ equality, and the classical limits of every mechanism. MIT licensed. This effort is supported by Qollab & IonQ.

5. Optional: running on IonQ

IonQ's simulator and hardware never add or subtract points, and nothing in this project depends on them. If you do want to run the same circuits there:

python -m pip install -e ".[ionq]"
export IONQ_API_KEY=...            # the CLI and the library read it from the environment
qcog run question-order --backend ionq --shots 1024

Q-Cog compiles each question onto the qubits it concerns and, for the branch construction, avoids mid-circuit measurement and reset entirely (build_prefix_circuit), so the circuits map onto restricted device gate sets after a standard transpile. demos/examples/03_hardware_and_ionq.py prints both compilations and their properties, so you can inspect them before submitting anything.

6. Regenerating everything

python scripts/generate_docs.py        # docs/models.generated.md from the code
python demos/examples/05_catalogue_report.py # out/qcog_report.html + .md
qcog evidence                          # the verification table

The parameter values used in a published run are printed in the report, together with the backend, the shot count and the seed, so any figure in the report can be regenerated from the page itself.

7. Support

  • Platform, submission or hardware problems: the Qollab support channel for your university node.
  • Problems with this project: open an issue with the model slug, the parameters, the backend and the output of qcog evidence.
